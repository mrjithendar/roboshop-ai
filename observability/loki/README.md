# Loki + Grafana Alloy

Promtail reached end of life on March 2, 2026;
[Grafana recommends Alloy](https://grafana.com/docs/alloy/latest/set-up/migrate/from-promtail/).
Pinned versions: Loki 3.7.9 and Alloy 1.21.2.

## Deploy

Publish these repository changes to `master`, then:

```bash
./deploy-argocd.sh loki grafana --context mk4
```

This syncs the Loki/Alloy Application and the existing Grafana Application. It does
not install another Grafana. Open **https://jithendar.com/grafana/** → Explore →
**Loki** and query `{namespace="roboshop-ai"}`, `{namespace="traefik"}` or
`{namespace="observability"}`.
No new password is needed; use your existing Grafana login. Loki is ClusterIP-only,
with no public ingress or built-in authentication. Trusted cluster workloads can
reach it; don't expose port 3100 externally. API collection uses RoleBindings
limited to pods/pods-log in those three namespaces, not Secrets or cluster-admin.

## Resource and data boundaries

- Loki: one pod, 256Mi request / 1Gi limit, 10Gi PVC, seven-day retention.
- Alloy: one pod, 128Mi request / 384Mi limit, 1Gi PVC for read positions. Prometheus scrapes Loki and Alloy.
- Existing Grafana/Prometheus remain. This is a single-host lab, not HA.
- Minikube hostPath volume capacity may not enforce a quota. Monitor host free disk.
- Alloy tails Kubernetes API streams, reducing host privileges at the cost of API
  and kubelet traffic. One replica avoids duplicate collectors. Reconnect/restarts
  can replay or miss logs outside the container log retention window; not exactly-once.
- Only namespace/pod/container/service labels are indexed. Trace IDs stay in lines.
- Raw messages, user data, prompts, headers, URLs and
  stack traces are discarded. Stored lines contain safe event/level/trace fields;
  unsupported plaintext becomes `application_log` rather than leaking raw content.
- Source Kubernetes timestamps are preserved. Local Loki/Alloy transport is HTTP within the
  trusted lab; use authenticated TLS and enforcing network isolation for production.

## Verify

```bash
kubectl --context=mk4 -n monitoring get pods,pvc
kubectl --context=mk4 -n monitoring logs deployment/alloy --tail=60
kubectl --context=mk4 -n monitoring logs deployment/loki --tail=60
python3 -m pytest -q tests/test_loki.py tests/test_argocd_catalog.py
kubectl kustomize observability/loki > /tmp/roboshop-loki.yaml
```

Argo deploys published Git, not local edits. No automatic replacement of the live
stack occurs just by editing these files. Persistent credentials from the old stack
are no longer generated by `create-secrets.sh`.
